# Git vs SVN — сравнение

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто **указатель на коммит** (файл размером 41 байт со SHA-хешем).
Создание ветки не копирует файлы, а лишь записывает новую ссылку. Поэтому `git branch`
срабатывает мгновенно и не занимает места.

В SVN ветка — это **физическая копия директории** внутри репозитория (`/branches/feature-x/`).
Сервер создаёт отдельную структуру каталогов, копирует туда файлы (пусть и с экономией
на дельтах, но всё равно это операция на сервере, требующая сети и времени).
Поэтому ветвление в SVN — медленное и «дорогое».

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

**Нет.** SVN — централизованная система: вся история и все операции с коммитами
проходят через центральный сервер. Без сети нельзя сделать `svn commit`.
Локально можно только редактировать файлы (и то `svn status`/`svn diff` частично
работают на локальной копии `.svn`), но зафиксировать изменения — только на сервере.

В Git коммит делается локально (`git commit`), а `git push` — уже отдельная операция,
требующая сети. Поэтому в Git можно спокойно работать в самолёте.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- **Legacy-проекты** (госсектор, банки), где SVN уже используется и миграция дороже,
  чем поддержка.
- **Очень большие бинарные репозитории** (графика, CAD, игры) — SVN позволяет
  выкачивать только часть дерева (`svn checkout --depth`), Git же клонирует всю
  историю целиком.
- **Строгий контроль доступа к отдельным папкам** — в SVN права раздаются
  по путям, в Git — на весь репозиторий.
- **Команды с жёсткой централизацией**, где не нужны распределённые фичи
  (офлайн-коммиты, локальные ветки).
- **Простые линейные проекты** без сложного ветвления — там SVN проще в освоении.
